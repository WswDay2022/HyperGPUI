# G06 — 小路径批次的全尺寸 MSAA resolve 基线

## 复现条件

基线 `6458c760f7`，Windows DX11，实际运行 GPU 为 **AMD Radeon RX 580 2048SP**，无 WARP 性能回退。生产的 `draw_paths_to_intermediate` 对每个路径批次清除 4× MSAA 中间纹理，使用路径栅格 shader 绘制，再用 `ResolveSubresource` resolve 到同尺寸 BGRA8 纹理。WGPU 和 Metal 也以路径中间目标为范围执行 attachment resolve，但本轮没有量这两个后端的 GPU 成本。

夹具复用生产资源创建函数、已编译路径栅格 shader 与 blend state。固定 **32×32 包围盒的同一个带分数像素原点的三角形、3840×2160 逻辑 viewport、4× BGRA8**，只改变底层中间纹理尺寸：4K、1080p、128×128。计时前每种尺寸都回读红色路径内部与透明背景，确认真正绘制到相同像素位置。申请纹理、上传路径、回读以及最终复制到父目标均不在计时里。

每个 GPU timestamp 样本 24 批，每种尺寸与模式各 7 个样本、循环交替顺序，取中位数；两次独立运行。`resolve` 模式在计时前先清屏并绘制，避免只 resolve 一张未消费的全清屏纹理。分模式数据不作精确加减归因；驱动状态不同，有时也会有离群值。

## 实测 GPU 时间

单位 **ms / batch**，表中范围是两次运行各自的中位数之间的范围。

| 逻辑 viewport 相同，纹理尺寸变化 | 仅 draw | clear + draw | 仅 resolve | clear + draw + resolve |
|---|---:|---:|---:|---:|
| 3840×2160 | 0.00069–0.00075 | 0.01337–0.01421 | 0.24045–0.27811 | **0.25823–0.28967** |
| 1920×1080 | 0.00075–0.00079 | 0.01201–0.01307 | 0.07063–0.07533 | **0.08687–0.09209** |
| 128×128 | 0.00079–0.00081 | 0.01136–0.01224 | 0.00549–0.00591 | **0.02041–0.02201** |

在夹具中，4K→128×128 的全链减少约 **92%**，每批省 **0.238–0.268 ms**。同一测试若连续 24 批，4K 全链约 **6.20–6.95 ms**、小目标约 **0.49–0.53 ms**。这是测得的路径中间 pass 时间，不是应用帧时，不代表应用每帧有 24 个这种批次，也不是 WGPU/Metal 的实测提速。

**结论：首要成本是 resolve，不是三角形，也不是 clear。** clear+draw 只从约 0.014 到 0.012 ms，未随面积成比例缩小。这个结果与快清除一类机制相符，但没有内存计数器，不能断言驱动的实际写入量，也不因此删除必要清屏。

## 实现建议与验收门

- 推荐真正缩小 MSAA/resolve 附件，按每批的可见像素包围盒，向外取整并为采样留边；较大或分散的批次走原路径。仅加 scissor 不能缩短 DX11 的 `ResolveSubresource` 作用域。
- 继续使用原 4× MSAA 和透明初值，保持场景坐标参与渐变及 mask、局部纹理坐标参与采样，保持交错图元顺序与透明区域只合成一次。池化尺寸、复用和原路径回退需同时设计，不能因每批重新分配抵消收益。
- 实现必须同时覆盖 DX11、WGPU、Metal。用非零起点、分数边缘、复杂蒙版/渐变、两批路径交错及尺寸切换与原路径做回读 A/B，再跑同一 GPU 夹具。Mac 待在可用机器上验证，不能继承 RX 580 的倍率。
- 本轮只加入 Windows 实卡测量夹具和文档，未改运行时代码、采样数、清屏或呈现。Windows 原生库 **50 通过 / 3 默认忽略**；新增 ignored 硬件基准实际独立跑了两次，均通过。
